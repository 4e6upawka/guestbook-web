# GuestBook.Web — лабораторные №5–11 на локальном Azurite

Проект восстановлен по методичкам №5–6, №7, №8–9 и №10–11. **Azure подписка не нужна**. Для №7 облачное развёртывание заменено локальным запуском.

## Требуется
- .NET 8 SDK; Azurite (`npm install -g azurite`); Visual Studio 2022 (необязательно); Azure Storage Explorer (для проверки).

## Запуск (два окна PowerShell, на одном компьютере)

Окно 1:
```powershell
mkdir C:\azurite-data -Force
azurite --location C:\azurite-data
```
Должны быть открыты 127.0.0.1:10000 (Blob), 10001 (Queue), 10002 (Table).

Окно 2: перейдите в папку, содержащую `GuestBook.Web.csproj`:
```powershell
dotnet restore
dotnet run --launch-profile GuestBook.Web
```
После строки `Now listening on: http://localhost:5080` откройте **http://localhost:5080**. Если порт занят, используйте `dotnet run --urls http://localhost:5099` и откройте порт 5099.

Важно: если Azurite работает **в виртуальной машине**, то браузер и приложение должны работать в той же машине. `localhost` на хосте — другой компьютер относительно VM.

## Что проверить
1. Добавьте запись и фото: создаётся запись в `GuestBookEntries`, файл в `guestbookpics`, сообщение в `guestthumbs`.
2. Фильтр по имени на главной; в Storage Explorer запрос `GuestName eq 'Иван'`.
3. Удалите запись кнопкой; обновите таблицу в Storage Explorer.
4. Откройте `/Gallery`, проверьте фото, удалите один файл и обновите контейнер в Storage Explorer.

Фото хранятся в приватном контейнере и показываются через серверный обработчик `/Index?handler=Photo&name=...`. Удаление записи **не удаляет** фото автоматически; удаление фото из галереи не удаляет запись в таблице. Очередь используется для демонстрации постановки сообщения, а не обработки миниатюр.

Не путайте: запуск Azurite не запускает ASP.NET сайт. Для сайта необходимо отдельно выполнить `dotnet run`.
